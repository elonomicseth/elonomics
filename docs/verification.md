**Remote preflight and first request.** On 8 October 2026 an initial remote preflight was run, with the result HTTP 200, disposition `needs_evidence`, `deployable` true, `routable` false, `featured` false, and no hard-block findings. Its needs-evidence codes were `SOURCE_EXTERNAL_DEPENDENCY_SURFACE`, `SOURCE_LIQUIDITY_LOCK_OR_CUSTODY_SURFACE`, and `SOURCE_MUTABLE_TAX_OR_FEE_SURFACE`. Afterwards, the first request was submitted using a CLI 4.1.3 built from the Programmable source before the official release was published. The official CLI 4.1.3 (released 2026-10-08 13:16 UTC, sha256 `d169fc01…c131`), locked in `package-lock.json` until it was replaced by 4.1.4 on 9 October 2026, is byte-for-byte identical to the build used for that first request. That request was created before the manual review flow was active on the server: it has no `manualReview` object, remained `pending_review` while the server retried with `LAUNCH_UNAVAILABLE` (17 attempts), then ended as `failed` with `LAUNCH_WORK_EXPIRED` at the one-hour permit limit. No wallet handoff was produced and no funds were spent.

**CLI 4.1.4 and the successor Router.** On 9 October 2026 the official CLI 4.1.4 (release `programmable-launch-v4.1.4`, published 2026-10-09 09:37 UTC) was verified: the sha256 of `programmable-launch-4.1.4.tgz`, `b11e4bf19f7a8e47259fced126ee9a5859cec26175ff2d06ca2d8a642079567f`, matches the release's `.tgz.sha256` asset and its release manifest, and that asset was locked in `package-lock.json` until it was replaced by 4.1.5 on 10 October 2026. According to Programmable's release notes, CLI 4.1.4 packs new profile 3.6.0 requests for the successor Router `0xBE4bF6Ac8c6F012E1C8f25747A9fBccB2FDAC4C3`, whose signing deadline can be up to 24 hours after approval, while requests packed with CLI 4.1.3 keep the legacy Router and its one-hour limit. The successor Router is deployed on mainnet with the expected runtime hash `0xf2d611fb92718c63cf5767300e79d7c9b49480b2e9001448b96c1385f4edb6f3` (23,014 bytes of code) and returns the same GraphFactory and PoolManager bindings, so the contracts need no change. A profile 3.6.0 package packed with CLI 4.1.4 passed the remote preflight with HTTP 200, disposition `needs_evidence`, `deployable` true, and no hard-block findings.

**Manual review of the third request.** On 10 October 2026 Programmable's manual review rejected the third request with one required change: the hook's platform fee destination `0x4957f49620AFf3Adbbe8195a4f633E49cc93376c` had to become `0xD88539d3c4C460136a733A3Fd60cf6BF269079da`, Programmable's current treasury under its current policy, keeping the 0.30% allocation. The reviewer stated that this is a destination update, not a finding against the 0.30% calculation, noted that the fixed supply and the burn-address ownership of the initial LP position were consistent in the reviewed source, and stated that the launch and signing window after approval is 24 hours. The repository was updated accordingly: the hook constant, the tests, the tooling, and the CLI pin.
