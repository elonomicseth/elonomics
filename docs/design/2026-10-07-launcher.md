# Design: one-transaction launch with zap, burned LP and developer first buy

Status: approved 7 October 2026; updated 8 October 2026 with decisions made after approval: an ELON/TSLAon pair with SPCXon rewards, a zap through the 1% USDC/TSLAon pool, LP mint without Permit2, snapshot-based balance checks, a dev share of ≈ 1.75%, `docs/verification.md` and `docs/stock-tokens.md` in the documentation list, and Programmable profile `3.6.0`; the official CLI 4.1.3 release was locked in `package-lock.json` on 9 October 2026 and replaced the same day by the official CLI 4.1.4 release, which packs profile `3.6.0` requests for the successor Router `0xBE4bF6Ac8c6F012E1C8f25747A9fBccB2FDAC4C3`; updated 10 October 2026 after Programmable's manual review: the hook's platform recipient became Programmable's current treasury `0xD88539d3c4C460136a733A3Fd60cf6BF269079da`, and the official CLI 4.1.5 release replaced 4.1.4.

## Summary

The Programmable launch transaction (Ethereum Mainnet, chain ID 1) does everything in a single transaction: deploys the contracts, zaps the dev's ETH into TSLAon, opens the ELON/TSLAon pool, places 100% of the ELON supply as single-sided liquidity whose position NFT is sent directly to `0x000000000000000000000000000000000000dEaD`, then performs the dev first buy with all of the TSLAon from the zap. After that, anyone can buy and sell through third-party routers (Universal Router, GMGN, BasedBot, Banana, and similar) with exact-input swaps. Holder rewards are paid in SPCXon, which the processor buys with the TSLAon fee share.

This method follows the CLSTR launch on Programmable (tx `0x0befb5bb8353d7582785d67cc9969ad91c7dc90a35c2804e04130080c7b3859a`): the full supply to the launcher, a zap into the pair token, single-sided liquidity `[extreme, start tick]`, the LP NFT to `0x…dEaD`, the first buy in the same transaction, and hook fees recorded as ERC-6909 claims.

## Goals and success criteria

1. The dev needs only ETH. The launch transaction carries `devBuyEth` (example 0.02 ETH); the dev does not have to prepare any TSLAon or ELON.
2. The entire ELON supply (1,000,000,000) goes into liquidity; there is no team allocation. The dev obtains ELON only from the first buy.
3. The LP position NFT is owned by `0x…dEaD` from the moment it is minted. No party can withdraw the liquidity.
4. The initial price corresponds to an FDV of `initialFdvEth` (1.1 ETH). This price becomes ELON's lowest price because there is no liquidity below it.
5. Dev share = net funds ÷ (initial FDV + net funds), where net funds = the dev buy after the 2% fee. With 0.02 ETH and an FDV of 1.1 ETH, the dev obtains ≈ 1.75% of the supply (the initial draft said 1.73% because of a rounding error). The price tick is rounded to a multiple of 60, so the effective FDV shifts slightly; a sample quote of 0.134 TSLAon per 0.02 ETH gives an effective FDV of 1.10086 ETH and a dev share of 1.749%. This formula matches the reference launches (CLSTR 1.470%; `0x92c7…` 0.968%).
6. After the first buy, exact-input buys and sells through the mainnet Universal Router (including the ETH → USDC → TSLAon → ELON route in one transaction) succeed without reverting.
7. All steps fail atomically: if one step fails, the entire launch reverts and no contract is deployed.

## Out of scope

- A permanent zap contract for traders. Traders buy through their own routers.
- Exact-output swaps. The hook still rejects them; a "buy exactly X tokens" feature in any router will fail for ELON.
- Code changes to `ElonomicsFeeProcessor` (including moving the reward hop to the 0.3% USDC/SPCXon pool, which would require a per-hop fee and also has only one oracle observation).
- Changes to the `Elonomics` reward logic.

## Architecture

The graph still contains four CREATE2 targets:

| Target | Role | Change |
| --- | --- | --- |
| `token` (`Elonomics`) | ERC-20 ELON, SPCXon rewards | No code changes. `initialRecipient` = the predicted `launcher` address. |
| `hook` (`ElonomicsHook`) | 2% fee in TSLAon (1% rewards, 0.3% Programmable, 0.7% dev) | Fees are recorded as ERC-6909 claims; claims are redeemed through `unlock`. `initializer` = the predicted `launcher` address. |
| `processor` (`ElonomicsFeeProcessor`) | TSLAon → SPCXon dividend conversion | No code changes; the constructor arguments follow the new roles. |
| `launcher` (`ElonomicsLauncher`, new) | Zap, pool initialization, burned LP, first buy | Replaces `ElonomicsInitializer`. |

Roles in the Programmable profile: `tokenTargetId` = `token`, `hookTargetId` = `hook`, `initializerTargetId` = `launcher`, `platformFeeBindingTargetId` = `hook`. Liquidity model `launch-seeded-concentrated-liquidity` with `liquidityTargetId` = `launcher`, initial status `assessment_required`. Funding mode `wallet-transaction-value`: the Router transaction value = `devBuyEth`, forwarded as the `initializerValueWei` of the `launcher` target.

## The `ElonomicsLauncher` contract

### Immutable dependencies

`poolManager` (`0x000000000004444c5dc75cB358380D2e3dE08A90`), `positionManager` (`0xbD216513d74C8cf14cf4747E6AaA6420FF64ee9e`), Uniswap v3 `swapRouter` (`0xE592427A0AEce92De3Edee1F18E0157C05861564`), `weth` (`0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2`), `usdc` (`0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48`), `quote` TSLAon (`0xf6b1117ec07684D3958caD8BEb1b302bfD21103f`), and `graphFactory`. There is no `permit2` immutable. The zap route is fixed: WETH → USDC fee 500 → TSLAon fee 10000 (`WETH_USDC_FEE = 500`, `USDC_QUOTE_FEE = 10_000`), through the 0.05% WETH/USDC pool `0x88e6A0c2dDD26FEEb64F039a2c41296FcB3f5640` and the 1% USDC/TSLAon pool `0x31227b50eCCDC9C589826AA2D9E7C5619B1895Da`. That 1% pool is the deepest TSLAon pool and is the same as the processor's quote pool; the 0.3% USDC/TSLAon pool holds only about 2,200 USD and returns about 0.34% less at 0.02 ETH. The constructor verifies that every dependency other than `graphFactory` (which only needs to be a non-zero address) has code and, through the v3 factory, that both pools exist.

### `launch(token, hook, devRecipient, quotePerTokenTick, minimumQuoteOut)` — payable

Only `graphFactory`, only once. `msg.value` is the dev buy funding and must be greater than zero; `token` must not equal `quote`; the tick must be a multiple of 60 and lie within ±887220.

1. **Snapshot.** When `launch` starts, the launcher records its own ETH balance excluding `msg.value`, as well as its TSLAon, WETH, and USDC balances. The launcher address is predictable (CREATE2), so anyone can send dust there before launch; the snapshot-based checks mean that dust cannot make the launch fail. That dust stays held in the launcher.
2. **Zap.** `swapRouter.exactInput{value: msg.value}` with path WETH-500-USDC-10000-TSLAon, `amountIn = msg.value`, `amountOutMinimum = minimumQuoteOut`, recipient `launcher`. The result is `quoteIn` TSLAon; the launcher's TSLAon balance must increase by exactly `quoteIn`.
3. **Open the pool.** PoolKey `(ELON, TSLAon, fee 0, tickSpacing 60, hook)` with the currency order determined by address. `quotePerTokenTick` is the price tick of TSLAon per ELON (base units), a multiple of 60. If ELON = currency0, start tick = `quotePerTokenTick`; if ELON = currency1, start tick = `-quotePerTokenTick`. The pool is initialized exactly at `TickMath.getSqrtPriceAtTick(startTick)`; the hook accepts initialization only from `launcher`.
4. **Burned single-sided LP.** Range `[startTick, 887220]` if ELON = currency0, or `[-887220, startTick]` if ELON = currency1. At a price exactly on the range boundary, the position holds only ELON. Liquidity is computed from the launcher's entire ELON balance (`LiquidityAmounts`). The launcher transfers all ELON to the PositionManager, then runs `MINT_POSITION` with NFT owner `0x…dEaD`, `SETTLE` of ELON from the PositionManager's own balance for the open delta, and `SWEEP` of the remaining ELON to `0x…dEaD`. There is no Permit2 approval and no lingering permission. The unit tests deploy the PositionManager with a placeholder Permit2 address that this path never touches.
5. **Leftover dust.** ELON left unused because of rounding (a few wei) is also swept to `0x…dEaD`, as in CLSTR.
6. **First buy.** `poolManager.unlock`; in the callback (PoolManager only): an exact-input `swap` of all `quoteIn` TSLAon → ELON with MIN/MAX price limits and empty `hookData`; settle the TSLAon (`sync`, `transfer`, `settle`); `take` ELON to `devRecipient`. The 2% hook fee applies.
7. **Final checks** (revert on failure): ELON received by the dev > 0; `ownerOf(tokenId) == 0x…dEaD`; position liquidity > 0; launcher ELON balance = 0; launcher ETH, WETH, USDC, and TSLAon balances equal the step 1 snapshot.
8. Emit `Launched(token, hook, poolId, tokenId, ethIn, quoteIn, elonToDev)`.

The launcher has no owner, no withdrawal function, and no other function that can change the position after `launch`.

## `ElonomicsHook` change: ERC-6909 fees

Problem: `_accrue` previously called `poolManager.take` before the swapper paid. A single-sided pool starts with little TSLAon, so a buy through a router that pays after the swap could revert or be limited to ≈ 50× the TSLAon in the PoolManager.

Changes:

- `_accrue` calls `poolManager.mint(address(this), CurrencyLibrary.toId(quote), total)`. No tokens move during the swap; the delta is neutral after the swapper pays. The split and rounding are unchanged (`previewFees`: total = gross/50, platform = 3/1000, dev = 7/1000, remainder to rewards).
- `claimDividends`, `claimPlatform`, `claimDev` remain permissionless and pay the fixed recipients; `claimPlatform` pays the `platformRecipient` constant, Programmable's current treasury `0xD88539d3c4C460136a733A3Fd60cf6BF269079da`. Each calls `poolManager.unlock`; `unlockCallback` (PoolManager only) performs a `burn` of the claim, then a `take` of TSLAon to the recipient, and verifies that the recipient received the exact amount.
- The hook permission mask stays `0x20cc`. The exact-input-only rule and the rule that buys must fill completely remain.
- Invariant: (accrued − claimed) for the three recipients = the hook's ERC-6909 claim balance in the PoolManager.

## Programmable package, config, and tooling

**Programmable profile.** The package targets profile `3.6.0` (Ethereum Custom Launch V3). This profile has been active since 7 October 2026 and is the only version that accepts new requests; profile `3.3.0` can only be read and replayed exactly. Profile `3.6.0` binds the 3000 (0.30%) platform fee in `platformFeePolicy` and `platformFeeBinding`; with an `inclusive-selected-total` selection of 20000 for buys and sells, the project share becomes 17000 (1.70%) and the Programmable share 3000, matching the hook split. The server treats 0.30% as a declaration bound to the request hash, not as a verified fee. The package is built with the `@programmable/launch` CLI 4.1.5 or later. The official 4.1.5 release (`programmable-launch-v4.1.5`) is locked in `package-lock.json`; like 4.1.4 it binds new requests to the successor Router `0xBE4bF6Ac8c6F012E1C8f25747A9fBccB2FDAC4C3` with the unchanged GraphFactory, while CLI 4.1.3 bound them to the legacy Router `0x8622DD5bAb44185f2A458ac90384Ac99248f8d56`. Before the official 4.1.3 release was published, development and rehearsal used a candidate built from production commit `6a99f03acdffd6302e81c614229986cd24945cb0`. The pack config omits `profileVersion`, so each pack is a fresh CLI pack that reads `/v3/capabilities` and embeds the current profile and treasury policy; an explicit version would keep the earlier treasury policy, and the CLI library default is still `3.3.0`. The pack config's `payoutRecipient` is read from the compiled hook's `platformRecipient`, and the CLI refuses to pack if it differs from the recipient of the current policy.

**Programmable routing fee policy.** Profile `3.6.0` adds `programmableTradeFeePolicy`: trades that go through Programmable's own ETH route are charged an extra 30 bps on the ETH side (buys are deducted before the swap, sells from the ETH output), and paid to Programmable's treasury `0xD88539d3c4C460136a733A3Fd60cf6BF269079da`, except for pools that run Programmable's exact Native30 hook and vault runtime. A custom hook allocation does not automatically waive it: the API verifies the applicable collection mode per trade. This policy does not apply to external routers (Universal Router, aggregators, bots) and does not change the hook fee. In the 8 October 2026 research, Programmable website swap routes were only created for pools with native ETH as `currency0`, so the ELON/TSLAon pool has no website route and the routing fee does not apply to ELON trades; if Programmable later routes ERC-20 pools, those 30 bps would be charged on top of the 2% hook fee, which already includes the 0.3% Programmable share. Programmable's revenue from ELON is only the 0.3% hook share in TSLAon, paid by `claimPlatform()` to `0xD88539d3c4C460136a733A3Fd60cf6BF269079da`.

**`launch.config.json`** (all amounts are decimal strings):

| Field | Description |
| --- | --- |
| `launchWallet` | Wallet that sends the launch transaction and owns the API key (`0x9806…63C0`). |
| `devRecipient` | Recipient of the 0.7% dev fee (`0x6E55…1756`). |
| `devBuyRecipient` | Recipient of the ELON from the first buy (default `launchWallet`). |
| `initialFdvEth` | Initial FDV in ETH (`"1.1"`). |
| `devBuyEth` | ETH carried by the launch transaction (`"0.02"`). |
| `zapSlippageBps` | Tolerance for the zap minimum output (default `300`). |
| `zapQuote` | Filled in by `npm run quote`: quote block and time, `quoteOut`, `minimumQuoteOut`, `quotePerTokenTick`, and the effective FDV. |
| `website`, `x`, `imageSourcePath`, `imageUri`, `publicSourceUrl`, `publicSourceRevision` | As before. |

The fields `initialRecipient`, `initialPriceSpcxPerElon`, `initialLiquidityElon`, `initialLiquiditySpcx`, and `liquidityRecipient` are removed.

**`npm run quote`** (new, needs `MAINNET_RPC_URL`): reads the Uniswap v3 quote for `devBuyEth` along the zap route, computes `minimumQuoteOut = quote × (1 − zapSlippageBps)`, computes the TSLAon-per-ELON price from `initialFdvEth`, converts it to the nearest tick that is a multiple of 60, then writes the result to `zapQuote`. `pack` stays offline and deterministic with respect to the config. Config validation recomputes the minimum, tick, and effective FDV from `quoteOut` together with the supply, `devBuyEth`, `initialFdvEth`, and `zapSlippageBps`, so a hand-edited quote is rejected. `pack` rejects a quote older than 30 minutes when creating a new session; re-packing the same session within the permit window is still allowed.

**`scripts/launch.mjs`**: targets `token`, `hook`, `processor`, `launcher`; the token constructor uses `ref('launcher')` as the supply recipient; the hook constructor uses `ref('launcher')` as the initializer; the launcher initializer is `launch(ref('token'), ref('hook'), devBuyRecipient, quotePerTokenTick, minimumQuoteOut)` with `initializerValueWei` = `devBuyEth`; `fundingMode` `wallet-transaction-value`; liquidity model `launch-seeded-concentrated-liquidity`; profile `3.6.0` selected by a fresh CLI pack from current capabilities. The 0.30% (3000) platform fee guard still applies; `pack` and `validate` also reject CLIs below 4.1.5 and packages that are not profile `3.6.0` with a 2% total and a 1.70% project share for the successor Router, or whose platform fee claim authority, payout recipient, or embedded routed-trade policy names anyone but the hook's `platformRecipient`.

**`scripts/transactions.mjs`**: the `liquidity` command is removed. Buy, sell, claims, `prepare-oracle`, and `convert` remain.

**`scripts/check-mainnet.mjs`**: adds checks for the zap route pools (WETH/USDC 0.05% `0x88e6A0c2dDD26FEEb64F039a2c41296FcB3f5640`, USDC/TSLAon 1% `0x31227b50eCCDC9C589826AA2D9E7C5619B1895Da`), the zap quote, asset identities under the new roles, and live capabilities and `/readyz`: profile `3.6.0` selected, `3.6.0` present in `freshSubmissionExactVersions`, platform fee 3000, and the routing fee policy: its pinned hash, the same hash recomputed from the published body, and both recipients equal to the hook's `platformRecipient`. Profile and fee are not checked against the manifest, because manifest version 12 still lists profile `3.3.0`.

**`npm run readiness`** (new): read-only checks before submit, one `PASS`, `WAIT`, or `FAIL` line per check: config, quote age together with whether `quotedAt` matches the quote block's timestamp, Node and CLI versions, capabilities, launch wallet balance (`devBuyEth` + a 0.02 ETH gas reserve), public source at the pinned revision (including the image file, which is part of the source bundle), image, website, presence of the API key, package (must come from a session created from the current config, source, build, and image, so a package from an old quote does not pass), and the locked CLI release. It prints neither the RPC URL nor the API key.

**Documentation**: README, `docs/operations.md`, `docs/programmable.md`, `docs/stock-tokens.md`, and `docs/verification.md` are updated to this flow.

## Third-party router compatibility

Guaranteed by design: ERC-6909 fees (independent of payment order), liquidity up to the extreme price so that exact-input buys through the Universal Router (MIN/MAX price limits) always fill completely, `hookData` is ignored, ELON is a standard ERC-20 without a transfer tax, and buys and sells are both open with a 2% fee.

Not guaranteed: whether GMGN, BasedBot, Banana, or other platforms index and route hooked v4 pools with a TSLAon quote. Routers that use exact-output swaps will fail. The Programmable website does not provide a swap route for this pool.

## Operational conditions

- The 1% USDC/SPCXon reward pool stores only 1 oracle observation, so `observe([1800, 0])`, and therefore `convert`, succeeds only while that pool's last swap is at least 30 minutes old, then fails again after every new swap. Before relying on `convert`, run `prepare-oracle` to raise the oracle capacity (about 10.3 million gas in the research), then wait for 30 minutes of history to fill through pool activity. The 1% USDC/TSLAon pool has 48 observations and 39 hours of history; its capacity is also raised to 256.
- The TSLAon market is thin: the 1% USDC/TSLAon pool is worth about 72,000 USD and is the only viable TSLAon pool. Buyers starting from ETH pay v3 pool fees of about 1.05% before price impact, on top of the 2% hook fee.
- TSLAon and SPCXon use one and the same Ondo pause manager, beacon, and compliance contract. A TSLAon pause halts the launch zap, every ELON buy and sell, and hook fee claims; an SPCXon pause halts conversion and reward claims.

## Error handling

| Condition | Result |
| --- | --- |
| Zap output < `minimumQuoteOut` (price moved since the quote) | Launch reverts (`Too little received`); the permit is not yet used; if the permit window has passed, re-run `quote` and `pack`. |
| TSLAon rejected by the issuer (pause/blocklist for the launcher, hook, PoolManager, or PositionManager) | The server-side Router simulation fails; the launch is not authorized. |
| `launch` called by anyone other than GraphFactory, or a second time; `unlockCallback` called by anyone other than PoolManager | Revert. |
| Invalid `launch` arguments (zero value, token = quote, tick not a multiple of 60 or outside ±887220, zero minimum, zero recipient) or constructor dependencies without code | Revert. |
| Final check fails (dev ELON 0, NFT not owned by `0x…dEaD`, liquidity 0, leftover ELON, ETH/WETH/USDC/TSLAon balances differ from the snapshot) | Revert. |
| Dust sent to the launcher address before launch | The launch still proceeds; the dust stays held in the launcher. |
| Fee claim to a recipient blocked by the issuer | Only that claim reverts; other claims and swaps keep working. |
| Permit window ends before the wallet sends | Reissue is not supported; re-run `quote`, `pack`, and submit with a new nonce, so all CREATE2 addresses change. |

## Risks and dependencies

- Profile `3.6.0` (0.30% platform fee) has been active since 7 October 2026. The official CLI release is locked in `package-lock.json` (4.1.4 since 9 October 2026, 4.1.5 since 10 October 2026), so `npm ci` at a public revision that contains that lock installs a CLI that packs profile `3.6.0` for the successor Router and Programmable's current treasury; the public revision must be pinned again after that change.
- The `launch-seeded-concentrated-liquidity` model and external protocol calls (the v3 zap) are among the features that require additional evidence in Programmable admission. Profile `3.6.0` does not yet run its three-vector liquidity assessment, so the liquidity and fee claims remain unverified by the server.
- ELON will be the first V3 launch with an ERC-20 quote and the first finalized profile `3.6.0` launch on Programmable.
- The ETH/TSLAon rate can shift between `quote` and execution (permit window ≤ 1 hour); the 3% tolerance determines how large a shift is accepted, and the TSLAon market is thin.
- The API key must be bound to `launchWallet` and its chain restriction must include Ethereum (1).
- Route availability in third-party bots is determined by each platform.
